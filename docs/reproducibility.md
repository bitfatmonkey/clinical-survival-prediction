# Reproduce the R-only analysis

## Requirements

R >=4.3 is required; the executed lock records R 4.5.3, which is the recommended version for exact reproduction. A newer lock package may itself require R >=4.4; use R 4.5.3 rather than assuming all locked versions install on the minimum version. All data processing, modelling, graphics, statistical tests and reporting are in R. No Python analytical workflow is used. Pandoc renders R Markdown HTML; no desktop or LaTeX is required.

Use the existing isolated checkout in cloud tasks; do not create an extra worktree. From the repository root:

```r
install.packages('renv', repos='https://cloud.r-project.org')
renv::restore()
```

```sh
Rscript scripts/run_all.R
Rscript scripts/test.R
```

The second command is optional after run_all.R, which already runs tests. To render without refitting, keep the ignored artifacts from the previous analysis and run `Rscript scripts/render_report.R`. The pipeline writes figures and reports to the checkout. It never pushes, merges, or changes branches. Seeds, three CV folds, grid, horizons and tree counts are specified in scripts/run_all.R; do not choose new settings based on test-set results.

## Cloud runtime prepared in this environment

Run with the supplied runtime/toolchain wrapper:

```sh
cd /workspace/clinical-survival-prediction
/workspace/r-environment/run-r Rscript scripts/run_all.R
```

The wrapper sets the R runtime, compiler library paths, workspace renv cache and two OpenMP threads. The .Rprofile activates project renv. `--vanilla` scripts must explicitly source renv/activate.R. The published base environment had R, TH.data, survival and randomForestSRC verified in a fresh task. This project additionally installed and executed riskRegression and pec; they are recorded in the updated project lock. Existing cloud onboarding validation scripts cover the original base environment and do not replace this project's full entry point.

New cloud snapshots must retain /workspace/r-environment/runtime, its native libraries/toolchain and /workspace/r-environment/renv-cache. Changes in this task are not automatically proof of a newly published environment snapshot. Network access to cloud.r-project.org (and dependency repositories used by installation) is needed for uncached restore. No private data, API keys or credentials are needed for the analysis itself.

## Linux system dependencies

For source-package installation on Debian/Ubuntu, provide a C/C++ compiler, GNU Fortran, make, CMake, pkg-config, BLAS/LAPACK, curl/OpenSSL/XML, ICU, GLPK and Cairo/font/image development libraries. A typical Ubuntu command is:

```sh
sudo apt-get update
sudo apt-get install -y build-essential gfortran cmake pkg-config libcurl4-openssl-dev libssl-dev libxml2-dev libicu-dev libglpk-dev libuv1-dev libx11-dev libcairo2-dev libfontconfig1-dev libfreetype6-dev libharfbuzz-dev libfribidi-dev libpng-dev libtiff-dev libjpeg-dev pandoc
```

Native dependencies in this cloud task are provided by the local conda runtime rather than registered in dpkg. renv's system-package checks can therefore warn about Debian package names even when the native libraries are present. The original setup verified C/C++/Fortran compilation, linking and execution. Do not disable TLS, signatures or artifact checksums to bypass install errors.

## macOS Apple Silicon

Install the native arm64 build of R 4.5.3 from CRAN, Xcode Command Line Tools (`xcode-select --install`) and a CRAN-compatible arm64 GNU Fortran toolchain when source packages need it. Use arm64 libraries consistently; do not mix Intel and arm64 R/library prefixes. CRAN binaries should be preferred when available. Pandoc can be installed through a standard macOS package manager or supplied by RStudio. randomForestSRC runs on CPU; no CUDA/GPU is needed. OpenMP availability depends on the R compiler toolchain; an appropriate serial build can work more slowly. Apple Silicon was not available for execution in this task, so native macOS restoration is guidance, not a verified result.

## Outputs and interpretation

- reports/: actual patient tables, KM estimates, HRs, diagnostics, tuning scores, final metrics, package/session records and a self-contained HTML report.
- figures/: actual headless Cairo PNG figures, referenced in README and report.
- artifacts/ (ignored): fitted models, prediction/evaluation results and cached report inputs.
- docs/: methodology, limitations and copied official dataset documentation.

The lockfile, R version, seeds, protocol and package-version CSV define the reproducibility contract. Test-set metrics must be regenerated by the entry point rather than manually edited. Statistical differences caused by platform arithmetic should be assessed with appropriate numeric tolerance, not by changing expected outcomes to force a pass.
